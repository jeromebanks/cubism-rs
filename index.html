Nightshift is an open-source orchestration tool. Its first job is to unblock Cubism development with dependency-aware work, bounded retries and inspectable evidence.

  1. PlanMilestone → slices → native dependencies.
  2. ExecuteAllocate attempt → native session → candidate.
  3. VerifyIndependent review → repair → integration.
  4. CompleteConfirmed merge → assembled demo → human acceptance.

Attempts are execution records on slice issues. A retry does not create another work item.

The recommended starting point

GitHub owns the work graph.
Executors own their sessions.

GitHub-native records

Issues, sub-issues and blockers describe work. Compact comments journal attempts. Git, PRs, Checks and statuses identify candidates and verification.

One local dispatcher

Schedule, reconcile, enforce limits and commission review. The trusted effect broker is a module in this process. Serial attempts first.

Native execution

Codex, Claude Code, optional Factory Droid and qualified future adapters retain transcripts, context and checkpoints. Cubism receives optional asynchronous events.

No persistent Nightshift infrastructure: no PostgreSQL, SQLite, Dolt server, Temporal or custom distributed control plane in the default profile.

GitHub IssuesAttempt commentsExisting CIExecutor sessionsIn-process brokerOptional Cubism / OTel

Beads with embedded Dolt is optional later. Concurrent graph writers can justify Dolt server mode. Distributed runtime coordination requires an explicit safety or scale trigger and one named graph authority.

Small architecture, explicit boundaries

Protected effects stay trusted.

  • One dispatcherLocal process ownership and current-attempt capabilities; no cross-host concurrency guarantee.
  • No agent integration credentialsSandbox access to secrets and broker code. Agents return candidates and structured requests.
  • Separate reviewFresh reviewer session, exact reviewed SHA, structured verdict and carried blocking findings.
  • Protected policyRead from protected/default branch or another trusted source. Candidate policy cannot approve itself.
  • Honest recoveryReconcile comments, sessions, PRs, commits and checks. Unknown effects block blind retries.
  • Bounded costsLimit attempts and runtime, include failed work, expose unknown spend. Analytics is never required for scheduling.

Comments are modest durability, not database transactions or permanent audit evidence. Restart can abandon work or duplicate bounded computation; broker effects remain fenced and reconciled.

Human attention at coherent checkpoints

Verify the assembled outcome.

A real integration slice verifies the milestone's combined source and demo. One compact report identifies included work, criteria, evidence, exact source, limitations and cost.

Source and PRsTest and review summariesReproducible demoKnown gapsHuman GitHub decision

Approval names the exact checkpoint. Feedback authorizes linked corrective slices. Merge, release, deployment and acceptance remain distinct; release and deployment are disabled by default.

Pause first stops new admissions, then settles submitted effects. It cannot undo a merge already in flight. Raw Actions artifacts and native transcripts may expire.

Demonstrate value before adding systems

Unblock Cubism first.

STAGE 0Repair and qualify

Fix merge/receipt/gate enforcement and establish the trusted single-host boundary using existing tooling.

STAGE 1One complete milestone

Run dependent slices with allocation comments, native sessions, independent review, repair and crash reconciliation. Demonstrate integration and human acceptance.

STAGE 2Measure and selectively extend

Add another executor and asynchronous Cubism analytics when useful. Introduce local parallelism, Beads, remote compute or stronger retention only for a demonstrated need.

The first proof is a completed milestone under interruption.

No automatic progression to an enterprise control plane. No architectural question blocks beginning the local profile; live executor isolation and GitHub protections are qualification gates.
